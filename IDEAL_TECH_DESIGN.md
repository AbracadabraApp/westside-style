# Westside Style - Ideal Technical Design Document

**Project:** Westside Style Hair Salon Website
**Date:** 2026-08-25
**Status:** Recommendation Document
**Purpose:** Define the ideal technical architecture based on current state analysis

---

## Executive Summary

This document defines the **ideal technical architecture** for the Westside Style website based on analysis of existing code, documentation, and identified gaps. The current implementation has achieved significant functionality but suffers from **lack of standardization, inconsistent patterns, and missing centralized asset management**.

### Critical Issues Identified
1. **No CSS stylesheet files** - All styles are inline `<style>` tags in each HTML file
2. **No centralized component includes** - Modal/form components copied into each HTML file
3. **Inconsistent paths** - Mix of absolute (`/`) and relative paths across files
4. **No build system** - Manual Python scripts for deployment instead of proper tooling
5. **Fragmented documentation** - 20+ MD files with overlapping/contradictory information
6. **No version control discipline** - Broken deployment references, backup folders in repo

### 3.2 Module Pattern

**forms/contact.js**
```javascript
export const ContactForm = {
  init() {
    this.setupEventListeners();
  },

  getServiceType() {
    const path = window.location.pathname;
    if (path.includes('keratin')) return 'keratin_bond_extensions';
    if (path.includes('hand-tied')) return 'hand_tied_extensions';
    if (path.includes('tape-in')) return 'tape_in_extensions';
    return 'general_inquiry';
  },

  async submit(formData) {
    const response = await fetch('/api/send-sms', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(formData)
    });
    return response.json();
  }
};
```

**In HTML:**
```html
<script type="module">
  import { ContactForm } from '/assets/js/forms/contact.js';
  ContactForm.init();
</script>
```

## 4. Component System

### 4.1 Problem: No Include Mechanism

**Current State:**
- Python script (`deploy_forms.py`) copies component HTML into files
- 48 files must be updated when component changes
- No separation between content and presentation
- Risk of inconsistency

**Ideal Solutions (Pick One):**

#### Option A: Server-Side Includes (Simple)
```html
<!--#include virtual="/includes/header.html" -->
<main>
  <!-- Page content -->
</main>
<!--#include virtual="/includes/footer.html" -->
<!--#include virtual="/includes/modal.html" -->
```

**Pros:** Simple, no build step
**Cons:** Requires SSI support (Netlify supports via `_redirects`)

#### Option B: Build-Time Templating (Recommended)
Use a static site generator like **11ty**, **Hugo**, or **Astro**

**Example with 11ty:**
```html
---
layout: base.njk
title: Keratin Bond Extensions Seattle
---

<section class="hero">
  {% include "components/hero-video.njk" %}
</section>
```

**Pros:** Full control, fast builds, modern tooling
**Cons:** Requires Node.js build process

#### Option C: Web Components (Modern)
```html
<site-header></site-header>
<main>
  <!-- Page content -->
</main>
<site-footer></site-footer>
<contact-modal></contact-modal>

<script src="/assets/js/components.js" type="module"></script>
```

**Pros:** Native browser support, reusable, no build needed
**Cons:** Requires JavaScript, SEO considerations

### 4.2 Recommended: Use 11ty (Eleventy)

```javascript
// .eleventy.js
module.exports = function(eleventyConfig) {
  // Copy static assets
  eleventyConfig.addPassthroughCopy("src/assets");

  // Define layouts directory
  eleventyConfig.setLayoutsDirectory("src/layouts");

  // Define includes directory
  eleventyConfig.setIncludesDirectory("src/includes");

  return {
    dir: {
      input: "src",
      output: "dist"
    }
  };
};
```

## 5. Path Standardization

### 5.1 Problem: Inconsistent Paths

**Current State:**
```html
<!-- Mix of absolute and relative -->
<link href="/favicon.svg">                    <!-- Absolute -->
<img src="jennifer-headshot.jpg">             <!-- Relative -->
<script src="https://cdn.tailwindcss.com">    <!-- External CDN -->
```

**Ideal State:**

#### Rule 1: All Internal Assets Use Absolute Paths
```html
<link rel="icon" href="/assets/images/favicon.svg">
<img src="/assets/images/bio/jennifer-headshot.jpg">
<video src="/assets/videos/gallery/video-1.mp4">
```

#### Rule 2: CDN Assets in Config
```html
<!-- In head via config -->
<link rel="stylesheet" href="/assets/css/vendor.css"> <!-- Contains CDN CSS -->
```

#### Rule 3: API Endpoints via Environment
```javascript
// config.js
const API_BASE = process.env.NETLIFY_PROD
  ? 'https://westside.style'
  : 'http://localhost:8888';

const ENDPOINTS = {
  sendSMS: `${API_BASE}/.netlify/functions/send-sms`
};
```

## 9. Performance Optimization

### 9.1 Current Performance Issues

1. **Tailwind CDN on every page** (~400KB)
2. **Videos not optimized** (3.5MB files)
3. **No lazy loading for images**
4. **No caching headers**
5. **Google Fonts blocking render**

### 9.2 Ideal Optimizations

#### CSS Optimization
```javascript
// tailwind.config.js
module.exports = {
  content: ['./src/**/*.html', './src/**/*.js'],
  // Purge unused styles - results in ~10KB instead of 400KB
  safelist: []
};
```

#### Video Optimization
```bash
# Convert to multiple formats for browser support
ffmpeg -i input.mp4 \
  -c:v libx264 -crf 28 -preset slow output.mp4

# Generate poster images
ffmpeg -i input.mp4 -vframes 1 -f image2 poster.jpg
```

#### Lazy Loading
```html
<video preload="none" poster="/assets/videos/posters/hero.jpg">
  <source src="/assets/videos/hero.mp4" type="video/mp4">
</video>
```

#### Netlify Caching Headers
```toml
# netlify.toml
[[headers]]
  for = "/assets/*"
  [headers.values]
    Cache-Control = "public, max-age=31536000, immutable"

[[headers]]
  for = "/*.html"
  [headers.values]
    Cache-Control = "public, max-age=0, must-revalidate"
```

```javascript
import { checkLinks } from 'check-html-links';

checkLinks('dist/**/*.html').then(result => {
  if (result.broken.length > 0) {
    console.error('Broken links:', result.broken);
```



## 13. Maintenance Guidelines

### 13.1 Adding New Pages

**Old Way (Current):**
1. Copy existing HTML file
2. Manually update content
3. Ensure modal code is present
4. Run Python script to update forms
5. Test manually

**New Way (Ideal):**
1. Create new file in `src/pages/services/`
2. Use layout template
3. Write content in Markdown or HTML
4. Run `npm run dev` to preview
5. Components auto-injected
6. Deploy via git push

### 13.2 Updating Components

**Old Way:**
```bash
# Edit components/modal.html
python3 deploy_forms.py
# Manually test 48 files
```

**New Way:**
```bash
# Edit src/includes/modal.html
npm run build
# All pages automatically updated
npm run test  # Automated testing
```

### 13.3 CSS Changes

**Old Way:**
- Edit inline styles in one file
- Copy to 47 other files
- Hope you didn't miss any

**New Way:**
```bash
# Edit src/assets/css/components.css
npm run dev  # Hot reload sees changes
# Publish changes automatically to all pages
```

## Conclusion

The Westside Style website has solid functionality but lacks **engineering discipline**. Moving from inline styles and Python scripts to a proper build system with external CSS, component includes, and automated deployment would dramatically improve:

- **Maintainability:** Change once, update everywhere
- **Performance:** Optimized builds, smaller bundles
- **Developer Experience:** Hot reload, testing, clear structure
- **Reliability:** Automated checks, consistent output
- **Scalability:** Easy to add pages and features

**Recommended First Step:** Set up 11ty and extract CSS to external files. This solves the two biggest pain points without requiring massive refactoring.
